# BazarFX для Android — APK

Готовый APK: **`BazarFX.apk`** в этой папке (он же доступен с сайта — кнопка
«Скачать APK» на странице `/fx`, файл `public/BazarFX.apk`).

```
kz.bazar.fx · versionName 1.0 · minSdk 26 (Android 8) · targetSdk 34
подпись: v2 + v3 (debug-ключ) · 69 КБ · OpenGL ES 3.0
```

## Что делает приложение

1. Вы включаете тумблеры качества и нажимаете **«Включить поверх игр»**.
2. Android спрашивает разрешение на захват экрана (системный диалог — обойти нельзя).
3. Приложение уходит в фон, поверх всего появляется слой BazarFX, а в шторке
   висит уведомление с кнопкой «Остановить».
4. Открываете любую игру — кадр снимается через `MediaProjection`, проходит через
   пайплайн (`lib/fx` → GLES 3.0) и показывается в оверлее.
5. Плавающая кнопка **FX** поверх игры: тап — сравнить с оригиналом (bypass),
   удержание — выключить.

Пайплайн тот же, что в веб-демо: сцена низкого разрешения → Catmull-Rom апскейл →
Temporal (по желанию) → адаптивный шарп → (экспериментально) генерация кадров по
блочному оптическому потоку.

## Честно о возможностях

| Вопрос | Ответ |
| --- | --- |
| FPS игры вырастет? | **Нет.** Игра уже отрендерила кадр в своём разрешении, мы работаем с готовым изображением. Растёт резкость и (при генерации кадров) плавность вывода — но не частота кадров игры. |
| Тогда зачем? | Резкость/чистота картинки на любом устройстве, сглаживание лесенок, плавность для игр с локом 30 fps, единый «фильтр» поверх любых игр без модификации. |
| Как получить реальный FPS? | Игра должна рендерить сцену в низком разрешении: интеграция в движок (`integrations/unity/`) или root-хук (Magisk + GLES/Vulkan-слой). Внешнее приложение так не может. |
| Root нужен? | Нет. Работает через официальный `MediaProjection` + оверлей. |
| Задержка? | Снимаем ~1–2 кадра задержки на захват + обработку. Для шутеров держите генерацию кадров выключенной. |

## Установка APK

**С телефона (проще всего)**

1. Откройте страницу `/fx` на телефоне → кнопка **«Скачать APK»**.
2. Откройте скачанный файл → «Установить» → разрешите установку из этого источника.
3. Запустите **BazarFX** → «Разрешить показ поверх других приложений» (откроется
   настройки системы) → вернитесь в приложение → **«Включить поверх игр»**.

**Через ADB**

```bash
adb install -r integrations/android/BazarFX.apk
```

Если Play Protect ругается на неизвестный источник — это нормально для
debug-подписи, нажмите «Установить всё равно».

## Настройки

| Параметр | Что делает | Рекомендация |
| --- | --- | --- |
| Разрешение сцены | до какого размера сжимается кадр перед апскейлом | 60–80% для резкости, 40–50% «мягче, но дешевле» |
| Резкость | сила адаптивного шарпа | 40–70% |
| Temporal (TAA) | накопление кадров | выключено: без motion vectors даёт шлейфы |
| Генерация кадров | дорисовка промежуточных кадров | для игр с локом 30 fps; не для шутеров |
| Плавающая кнопка | кружок FX поверх игры | включено |
| Исключать оверлей из захвата | `FLAG_SECURE` на слое BazarFX | **включено** (иначе «зеркальный коридор») |

Настройки применяются при следующем включении сервиса.

## Сборка из исходников

Ни Gradle, ни Android Studio не нужны — обычный `aapt2 + javac + d8 + apksigner`.

```bash
cd integrations/android
# положите инструменты в tools/sdk (см. tools/FETCH_TOOLS.md)
JAVA=/path/to/java SDK_TOOLS=tools/sdk ./build.sh
python3 tools/check_apk.py BazarFX.apk
```

Скрипт собирает и **подписывает** APK, попутно выравнивая `resources.arsc`
через `tools/align_apk.py` (замена `zipalign`).

## Ограничения текущей версии

* Генерация кадров — экспериментальная: интерполяция по блочному потоку, на
  быстрых панорамах возможны артефакты, задержка растёт.
* Изменение настроек требует перезапуска (кнопка «Остановить» → «Включить»).
* Оверлей показывает захваченный экран, поэтому системные анимации и клавиатура
  тоже проходят через фильтр.
* Нет покадрового сравнения «до/после» в APK — только bypass по тапу на кнопке.
* Если при включении экран становится чёрным — выключите «Исключать оверлей из
  захвата»: на части прошивок (некоторые Samsung/Xiaomi) `FLAG_SECURE` приводит
  к чёрному кадру вместо контента под оверлеем.

## Версия 1.1 — исправление сбоя

Сбой «приложение остановлено» при запуске игры в ландшафте был вызван двумя ошибками:

1. **Повторный `createVirtualDisplay()` с тем же токеном MediaProjection.** Начиная с Android 14 это
   запрещено и бросает `SecurityException`. Пересоздание происходило в `onConfigurationChanged()` и в
   «стороже» поверхности каждые 1.5 секунды. Теперь VirtualDisplay создаётся **один раз**, а при
   повороте/смене разрешения вызывается `VirtualDisplay.resize()`, поверхность меняется через
   `setSurface()`.
2. **`SurfaceTexture.release()` при живом VirtualDisplay** — нативный краш. Теперь SurfaceTexture
   переиспользуется: `ensureSurfaceTexture()` + `resizeSurfaceTexture()`, без пересоздания.

Дополнительно в 1.1:

- файловый лог `filesDir/bazarfx.log` (`FxLog`), кнопки **«Лог»** и **«Отправить лог»** в главном экране;
- перехват ошибок GL-потока: любое исключение в `onDrawFrame` / компиляции шейдеров показывается в
  уведомлении, а не роняет процесс;
- детект чёрного захвата (FLAG_SECURE / DRM): вместо «сломалось» — понятное предупреждение;
- fallback компиляции шейдера с `#extension ... : enable` вместо `require` для капризных драйверов;
- версия `1.1` (`versionCode` 2), иконка в манифесте.

Если сбой повторится — BazarFX → «Лог» → «Отправить лог», и пришлите текст.

## Версия 1.2 — уровни качества («до реализма») и доработка движка

### Пять пресетов, меняются на ходу

| Пресет | Сцена | Проходы | Для чего |
| --- | --- | --- | --- |
| Экономия | 0.5× | апскейл + шарп | слабые устройства, максимум FPS |
| Баланс | 0.7× | + clarity | компромисс |
| Высокое | 0.85× | + TAA + тон | чище исходника |
| Ультра | 1.0× | + сильный clarity | предел апскейла |
| Реализм | 1.0× | TAA + clarity + антибандинг | максимум того, что можно выжать из готового кадра |

Переключение без перезапуска захвата: приложение → «Качество картинки»,
кнопка **«Качество»** в уведомлении, либо **удержание** кружка `FX` в игре
(тап по кружку — сравнение с оригиналом).

Новые проходы:
- **clarity** — локальный контраст на среднем радиусе, подавляется на сильных
  перепадах, поэтому края не получают белых ореолов;
- **grade** — мягкая S-кривая контраста, насыщенность и дизеринг ±0.5 LSB
  (убирает полосы на градиентах неба, тумана и теней).

### Что исправлено в движке

- **TAA с отбраковкой истории**: если пиксель заметно изменился, история не
  используется — на движущихся объектах больше нет «шлейфа».
- **Режим сравнения показывает оригинал как есть.** Раньше в bypass
  подставлялась сцена 0.7× (мыло) — сравнение было нечестным.
- **Ленивое выделение буферов**: hist-буферы только при TAA, prevLow/flow —
  только при генерации кадров. На «Экономии» память GPU не тратится зря.
- **Проверка полноты FBO** при создании (было: тихий чёрный экран).
- **Поток кадров**: prev-кадр копируется текстурой, а не повторным сэмплом OES.
- **Порядок остановки**: сначала `glView.onPause()`, потом `renderer.release()`
  (раньше можно было освободить SurfaceTexture во время отрисовки).
- **`START_NOT_STICKY`** — система больше не поднимает сервис без токена захвата.
- **Чёрный кадр** определяется по сырой сцене, а не по результату обработки
  (были ложные срабатывания на тёмных сценах).
- Уведомление обновляется раз в 4 с, а не каждую секунду.
- Настройки из приложения применяются к работающему сервису с задержкой 220 мс,
  чтобы перетаскивание слайдера не пересоздавало буферы 60 раз в секунду.
- Убраны 13 предупреждений компилятора (мёртвый код, неиспользуемые импорты).

Проверка шейдеров Android-пайплайна: `npm run check:shaders:android` (11 шейдеров).

## Версия 1.3 — исправлена ошибка «Не удалось начать захват»

Симптом: после нажатия «Включить поверх игр» появлялось уведомление
**«Не удалось начать захват: UnsupportedOperationException»**, оверлея не было.

Причина: `currentMetrics()` вызывал `Context#getDisplay()` (API 30+).
Контекст сервиса **не привязан к дисплею**, поэтому `getDisplay()` всегда
бросает `UnsupportedOperationException` — и старт падал на шаге показа оверлея.

Исправлено:
- размер экрана берётся через `DisplayManager.getDisplay(DEFAULT_DISPLAY)`,
  затем через `WindowManager.getDefaultDisplay()`, затем из ресурсов — три
  уровня, ни один не бросает исключение;
- старт разбит на 4 шага с отдельными сообщениями (`1/4 проекция`, `2/4 оверлей`,
  `3/4 GL`, `4/4 VirtualDisplay`) — в логе и в уведомлении видно, где именно упало;
- полный стектрейс пишется в `bazarfx.log` (кнопка «Лог»);
- уведомление об ошибке теперь сразу открывает лог в приложении;
- защита от повторного старта (`starting`/`running`), чтобы токен MediaProjection
  не использовался дважды;
- ошибки `addView` оверлея больше не глотаются молча.

## Версия 1.3.1 — чёрный экран после старта и лишняя видеопамять

По логу с телефона (Android 16, Mali-G57 MC2, 2340×1080):

```
Шаг 2/4: показываем оверлей
Смена размера: 2340x1080
E Не удалось пересоздать буферы: RuntimeException: Framebuffer неполный: 0x0
I Буферы: 2340x1080 → сцена 2340x1080, ~67 МБ видеопамяти
I GL готов: OpenGL ES 3.2 / Mali-G57 MC2
```

Причина: сервис сообщал размер сразу после `addView()`, а GL-контекст ещё не был
создан. `glGenFramebuffers` возвращал 0, `glCheckFramebufferStatus` — `0x0`, и
`fail()` **навсегда** помечал рендерер сломанным. Контекст создавался через
секунду, но `onDrawFrame` уже молча выходил — на экране ничего.

Исправлено:

- `onSurfaceSizeChanged()` до готовности GL только запоминает размер;
  применяется он в `onSurfaceCreated()`;
- ошибка выделения буферов больше не фатальна: ставится `targetsReady = false`
  и попытка повторяется на следующем кадре (игра могла временно занять память);
- одиночный сбой кадра пишется в лог, пайплайн останавливается только после 30 подряд;
- размер оверлея (2260×1080 из-за выреза) больше не перебивает размер захвата —
  источник истины теперь сервис, лишние пересоздания буферов убраны;
- **пресет «Реализм» (1.0×) больше не апскейлит 1:1**: кадр снимается сразу в
  полном разрешении, low-буфер уменьшен до пробника 320 px для диагностики;
- ленивые буферы: `scratch` только при clarity/grade, второй кадровый буфер
  только при генерации кадров. Память на 1080p: было ~67 МБ, стало ~40–50 МБ;
- защита от привязки нулевой текстуры к юниту (давала чёрный кадр при
  выключенной генерации кадров).

## Версия 1.4 — перевёрнутая картинка, «не нажимаются кнопки», скриншоты

Три жалобы из реального использования и их причины:

1. **Картинка вверх ногами.** Кадр из MediaProjection лежит в OES-текстуре
   строками сверху вниз, а GL читает текстуру снизу вверх. Не хватало переворота
   по вертикали при сэмплинге. Добавлено в шейдер `FRAG_SAMPLE` (и в passthrough,
   который использует тот же шейдер).
2. **«Не даёт нажимать кнопки».** Два фактора: перевёрнутая картинка (нажимаешь
   туда, где кнопка *нарисована*, а она физически в другом месте) и отсутствие
   `FLAG_NOT_TOUCH_MODAL`. Теперь окно явно не модальное и не принимает касания —
   все тапы уходят в игру.
3. **Не делаются скриншоты.** Это `FLAG_SECURE` на оверлее: без него
   MediaProjection снимал бы наш же слой и получался «зеркальный коридор».
   Системное ограничение. Решение — **скрыть оверлей, не выключая BazarFX**:
   удержание кружка FX → «Скрыть оверлей». Окно сжимается до 1×1 и теряет
   `FLAG_SECURE`, GL-поток перестаёт рисовать (нулевая нагрузка на GPU), захват
   остаётся живым. Возврат — тап по кружку или тот же пункт меню.

Дополнительно:

- `renderer.setOutputEnabled(false)` — при скрытом оверлее кадры не обрабатываются
  вообще (экономия батареи), а не «рисуются в невидимое окно».
- Кружок показывает состояние: `FX` (обработка), `OFF` (оригинал), `ON` (оверлей скрыт).

## Версия 1.5 — «не вижу улучшений» и «всё тормозит»

Причина не в шейдерах: оверлей показывает **копию** кадра, поэтому главный
враг — задержка и отсутствие наглядного сравнения. Сделано:

- **Сравнение «до/после»** — левая половина экрана исходная (прямо из
  MediaProjection), правая — после BazarFX, между ними зелёная линия.
  Включается в приложении или в меню кружка (◐). Это единственный способ
  увидеть разницу на живой картинке, не полагаясь на память.
- **Задержка измеряется и показывается**: в уведомлении `задержка 42 мс` —
  столько кадр идёт от захвата до экрана. Именно она даёт ощущение
  «кнопки не нажимаются»: касания уходят в игру мгновенно, а видишь ты их
  на кадр-два позже.
- **Авто-качество**: если вывод не успевает (меньше 22 fps), масштаб сцены
  автоматически снижается шагом 12% до 55%; когда появляется запас —
  возвращается. Убирает «тормозит так, что кажется сломанным» на слабых GPU.
- **Скрыть/Показать оверлей теперь кнопкой в уведомлении** — не нужно искать
  меню на кружке, чтобы вернуть игру и скриншоты.

### Что честно нельзя исправить

Полноэкранный оверлей с копией кадра всегда добавляет задержку и всегда
блокирует системные скриншоты (из-за FLAG_SECURE, без которого мы снимали бы
сами себя). Это цена работы без root. Настоящее улучшение без наложения
требует интеграции в движок игры — тогда кадр рендерится в низком разрешении
и апскейлится внутри, без копирования экрана.

## Версия 1.6 — нейросетевой апскейл (BazarFX-Neural)

Это то, о чём просили: не «умные шейдеры», а настоящая свёрточная сеть,
которая выполняется на GPU телефона в реальном времени.

### Архитектура

```
кадр 842×388 (низкое разрешение)
      ↓ conv 3→8, 3×3, ReLU
   8 каналов × 9 тапов
      ↓ conv 8→12, 3×3
   12 каналов = 4 подпикселя × RGB
      ↓ pixelshuffle ×2
 1684×776  →  Catmull-Rom до экрана  →  TAA / шарп / clarity / grade
```

- **1100 весов**, обучены офлайн: `python3 scripts/train_sr.py`.
- Данные обучения: 11 натуральных фотографий (scikit-image) + аугментация
  (флипы, повороты, гамма), 9000 шагов Adam, loss L1.
- Веса пакуются в одну RGBA32F-текстуру (276 текселей) и читаются шейдером
  через `texelFetch` — без запекания констант в шейдер.
- Первый слой рисуется в **два RGBA-таргета (MRT)**, второй — сразу в
  удвоенное разрешение: выборки `c0/c1` переиспользуются на все три выходных
  канала, это главный выигрыш по скорости.

### Качество (проверяемо, а не «на глаз»)

| Изображение | Билинейно | BazarFX-Neural |
| --- | --- | --- |
| astronaut | 28.04 дБ | **30.00 дБ** |
| coffee | 28.12 дБ | **29.17 дБ** |
| chelsea | 32.56 дБ | **33.94 дБ** |

Дополнительно `npm run check:neural` прогоняет **симуляцию шейдера** на тех же
упакованных весах и сверяет с numpy-моделью: расхождение 0.001 (только края,
где паддинг в GL отличается от im2col). Это ловит ошибки индексации до
запуска на телефоне — именно так был найден перепутанный порядок `tap × канал`
в первой версии экспорта весов.

### В приложении

- Пресет **«AI · нейро»** в списке качества (шестой).
- Чекбокс «Нейросетевой апскейл» и ползунок «Сила нейросети» (0–100%):
  0% — обычная математика, 100% — чистый выход сети.
- Авто-качество уменьшает и вход сети, если GPU не успевает.

### Честно про DLSS

Настоящий DLSS 5 восстанавливает кадр по G-буферам движка: глубина, векторы
движения, альбедо. Снаружи, через MediaProjection, этих данных нет — есть
только готовая картинка. Поэтому BazarFX-Neural делает то, что физически
возможно снаружи: нейросетевой SR по изображению. Это честный аналог не DLSS,
